# Runtime and redundant deployment decisions

## 2026-10-18: Preserve the VPS and add an independent Workers candidate

The canonical service remains the Deno VPS process in `deploy/ubiquity-rpc.service`, behind Caddy at `rpc.ubq.fi`. The retained Deno entrypoint uses the same KV keys and structured values. No route, DNS, VPS configuration, authoritative state, or scheduler ownership changes in this rollout. The legacy Deno Deploy workflow is manual-only recovery; canonical delivery deploys only the independent `uos-rpc-candidate` Worker in account `5c0228bee348f4cf48829ffe21b61fe9`.

The portable handler serves the existing numeric-chain JSON-RPC API, MCP initialization and tools, batch/notification and Multicall3 behavior, CORS, health, assets, and bidirectional WebSockets. Bun 1.4.0 is the local adapter and package manager; production Worker code executes in workerd through pinned Wrangler 4.151.1. The Deno VPS adapter remains supported, with its existing commands and service file. Bun-only and Deno-only adapters stay outside the Worker import graph.

Worker endpoint diagnostics are rebuildable advisory data with the existing four-hour freshness contract. HTTP diagnostic lookup and refresh use the private SQLite object described below; WebSocket diagnostics retain version-scoped, chain-granular Cache API storage. Neither shares or migrates VPS KV. Normal RPC requests read only their chain, and health reads the finite configured chain set without refreshing it. Only synchronous advisory health, circuit, capability, scoring, and round-robin state survives within a front isolate. Requests own their I/O, promises, sockets, and cache handles. There is no Worker cron or second hosted scheduler. Bun local development uses an in-memory advisory cache.

Workers Free allows a shared 50-call fetch/Cache API budget and 10 ms CPU per invocation, with 100,000 daily requests shared across the account. The original cold Ethereum selector uses 96 diagnostic requests. Workers batch the same bytecode, syncing, and chain-ID checks into one HTTP request per endpoint; providers that reject batches retain single-call fallback. If diagnostics cannot finish within one invocation, completed results persist and the client receives `-32005` with an explicit retry message; a later request resumes the missing checks before a complete ranking is used. This is an explicit free-tier warmup limit, not proof of immediate cold parity for every provider combination.

The shared 50-call application budget conservatively counts attempted front and child HTTP calls, redirect hops, binding calls, WebSocket upgrades, foreground/fallback attempts, and Cache API match/put operations. Cache API calls share the fetch quota and do not use the separate 1,000 internal-service allowance. HTTP diagnostics replace their two Cache API operations with one private binding call, not an extra uncounted hop. WebSocket diagnostics retain their cache-write reservation. Large JSON-RPC batches or unusually long retry paths can reach the combined budget and receive explicit errors. Budget errors retain code -32005 through sequential, hedged, and consensus execution without provider-health penalties. Unlimited VPS batch/retry capacity is not claimed for the Free candidate. CPU fit and public WebSocket/provider behavior require candidate measurements; a local workerd test does not enforce or prove the hosted CPU quota.

The committed server has no SSE or MCP long-poll transport. It forwards Ethereum filter RPC calls and keeps WebSocket subscriptions open; tests cover delayed filter responses and unsolicited subscription events. The adapters do not invent or remove a separate long-poll API. Worker binary frames are normalized to ArrayBuffer before acceptance so text/binary message order is preserved across the bridge.

Candidate validation uses actual workerd with isolated native upstream services, a real Bun listener, the retained Deno build/test gate, lint/format checks, generated bindings, and Wrangler dry-run. Public acceptance additionally requires exact committed revision and Worker version, candidate smoke checks, CPU/subrequest readback, Cache API behavior, and fresh VPS health before/after. The candidate has no canonical routes or cron triggers; traffic cutover remains separate authorization. Rollback leaves `rpc.ubq.fi` on the unchanged VPS and removes no resource or data.

## 2026-10-18: Private HTTP-only diagnostic compute boundary

Hosted cold Ethereum on version `76cc4126-b2e2-4791-b135-2f110f42029e` used 44 ms CPU despite succeeding, with 48 external plus two Cache API calls. Its warm control used 7 ms CPU and two calls. The preceding small logger/memoization experiment did not demonstrate the nominal 10 ms CPU fit and is superseded: its four production and three regression-file changes are reversed, while the accepted controller-backed WebSocket handshake timer fix remains. Successful burst requests are not evidence of sustained Free-plan CPU fit.

`HttpDiagnosticsObject` owns only advisory HTTP diagnostic lookup, full compiled-whitelist bytecode/sync/chain checks, and progress persistence. It reuses `LatencyTester`, `CacheManager`, and the existing selector/status-ranking algorithm. The front Worker retains the foreground JSON-RPC/MCP body, auth headers, capability/health/circuit/scoring/round-robin policy, all fallback/hedge/consensus work, and every WebSocket selection/upgrade/relay. Only a version/check identity, finite chain, eligible compiled endpoint indices, existing diagnostic options, request correlation ID and bounded call allowance cross the private RPC boundary. Unknown keys, arbitrary URLs, foreground bodies and headers are rejected. Health calls the distinct read-only snapshot method; it never invokes refresh.

Objects are named by platform colo and chain, not deployment version, avoiding a global bottleneck and unbounded per-deploy object creation. Each SQLite object retains at most two version/check-fingerprinted snapshots, each capped at 1 MiB and limited to its finite compiled endpoint set. Reads reject snapshots older than four hours; refreshes preserve completed results and merge concurrent updates atomically before pruning older fingerprints. Progress resumes the remaining checks rather than selecting a first-N subset. Existing cache-disable behavior performs fresh per-request checks without SQLite snapshot writes. There is no alarm, interval, scheduler, retained socket, stored request, pending background refresh or authoritative user state in the object. The Deno KV codec and keys are unchanged.

Before invoking refresh the root ledger charges the binding and full child allowance, preserving one foreground slot: a fresh request can delegate at most 48 calls. The child also independently enforces that allowance, including redirects and batch-rejection singles fallback. A receipt must match request ID, version, chain, allowance and bounded numeric counters before unused calls are refunded. Unknown RPC failure or an invalid receipt retains the complete reservation and surfaces terminal `-32005`; it cannot spend a hidden second 50-call pool. With batch-capable Ethereum fixtures, 32 child calls plus one binding and one foreground call total 34; a warm hit totals two. The previous 47-diagnostic/one-foreground public workload would conservatively total 49 after replacing Cache API calls, but this decomposition still needs actual staged hosted measurement.

Headers distinguish front, child, binding, Cache API and conservative unverified-child charges. SQL rows read/written and diagnostic active wall time are separate from the fetch ledger; opaque request IDs correlate exact child logs with front responses. SQL cursor row counters include the actual indexed storage work, not an assumed one-row price. Free DO request, row, storage and 128-MB active-duration quotas must be budgeted independently alongside the shared front Worker daily quota. No paid CPU limit or extra plan is required or configured. This implementation is not a hosted CPU acceptance claim: exact front/child CPU, duration, counters, public behavior and VPS after-health still require an explicitly authorized deployed-version checkpoint.
